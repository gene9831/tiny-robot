# 学习文档评审指南

本指南用于评审 Tiny Robot 的学习文档是否真的能帮助读者从具体场景出发，逐步形成完整且正确的框架理解。它是可重复执行的评审流程；强制写作规则见[下一代文档完整性规范](./documentation-standard.md)。

## 评审要证明什么

学习评审不是检查“文字是否看起来通顺”，而是证明目标读者能够仅凭文档：

1. 说清楚框架解决的问题；
2. 沿着一个具体场景解释输入、边界、状态变化和最终结果；
3. 区分各层职责、所有权和生命周期；
4. 预测关键失败或越界场景的稳定结果；
5. 判断新增能力应该扩展哪一层，以及必须保持什么不变量。

“完全理解”指达到当前文档承诺的学习范围，不要求记住全部 API 签名、未来能力或 Provider 私有协议。精确签名应当查询 API 参考，尚未实现的能力不属于当前学习验收。

## 三层评审

### 第一层：学习者评审

维护者或目标读者按推荐顺序阅读，不预先依赖代码、实施计划或评审对话。每个模块结束后，用自己的话回答：

- 本模块解决了什么问题？
- 场景从什么状态开始，最后得到什么？
- 新出现的核心概念分别由谁创建、拥有和消费？
- 哪个边界最容易被误解，越界时会发生什么？
- 下一层能力应从哪里扩展？

如果答案需要依赖文档之外的背景知识，或者只能复述名词而无法解释关系，本模块不能通过。

### 第二层：事实一致性验证

学习者理解不能替代自动验证。每次文档评审同时需要：

- 示例字段与当前公共类型一致；
- 可执行示例有类型检查或永久回归测试保护；
- Runtime TypeDoc 检查零 warning；
- VitePress 构建和内部链接通过；
- 图中的关系与类型、契约和永久测试一致；
- 当前能力、后续能力和临时实施材料没有混写。

### 第三层：陌生读者验证

在第一个端到端 Run、工具流程、Provider 接入和发布等重要里程碑，邀请没有参与当前设计讨论的开发者进行冷启动阅读。让对方完成一个小任务或复述完整链路，记录实际卡点，而不是先解释正确答案。

日常 Task 评审完成前两层即可；重要里程碑再增加第三层。

## 建议评审流程

1. 从文档首页进入，不使用浏览器历史中的深层链接。
2. 按主学习路径阅读，记录第一次需要跳读才能理解的位置。
3. 每个模块只记录读者观察到的问题，不先替作者设计修复方案。
4. 完成模块后的五个理解问题。
5. 再核对 API、ADR、契约和验证证据，区分教学问题与事实错误。
6. 修改后从出现问题之前的一个模块重新阅读，确认修复没有制造新的前置知识。
7. 运行自动验证，并记录仍未覆盖的风险。

## 问题分类

| 分类     | 判断方式                         | 常见修正                       |
| -------- | -------------------------------- | ------------------------------ |
| 目标缺失 | 不知道为什么要读或读完能做什么   | 补问题、场景和预期结果         |
| 顺序跳跃 | 当前段落依赖后文才解释的概念     | 前移最小定义或调整模块顺序     |
| 场景断裂 | 概念正确但无法放回完整流程       | 补就地示例或串联场景           |
| 抽象过早 | 尚未看到行为就先解释大量结构     | 先展示结果和主链路             |
| 边界模糊 | 无法预测失败、安全或生命周期结果 | 增加一个关键边界场景           |
| 扩展混乱 | 把未来字段、开发记录当成扩展性   | 改为稳定扩展点、责任层和不变量 |
| 事实漂移 | 示例、图或文字与公共类型不一致   | 修正文档，并补足必要的自动保护 |
| 入口错误 | 页面按 Task、目录或内部术语组织  | 改为读者目标和认知前置关系     |

评审反馈应描述读者在哪里失去理解以及缺少什么信息，避免只写“这里不清楚”。修复应补齐正向定义、场景或关系，不应不断追加否定句和修改历史。

## 通过条件

一次学习文档评审只有同时满足以下条件才通过：

- 评审者不借助代码和历史讨论，能够完成当前范围的五个理解问题；
- 主路径中没有必须跳到后文才能理解的未定义概念；
- 正常场景先完整走通，再进入边界与扩展；
- 示例、图、API、ADR、契约和测试没有相互矛盾；
- 自动文档检查与站点构建通过；
- 剩余未覆盖能力被描述为清晰的当前边界，而不是含混承诺。

评审者是学习质量的核心验收者，但“我理解了”不能单独替代事实一致性验证。反过来，构建和类型检查通过也不能证明文档具有可学习性。

## 可复制的评审记录

```md
## 学习文档评审

- 评审范围：
- 目标读者：
- 阅读起点：
- 阅读终点：

### 理解复述

1. 框架解决的问题：
2. 场景的输入、边界、状态和结果：
3. 核心职责与所有权：
4. 关键失败或越界结果：
5. 扩展位置与不变量：

### 卡点

- 页面/章节：
- 第一次失去理解的位置：
- 缺少的信息：
- 问题分类：

### 自动验证

- TypeDoc：
- 文档站构建与链接：
- 示例类型或永久测试：
- 图与契约一致性：

### 结论

- [ ] 当前学习范围可以仅凭文档完整理解
- [ ] 文档事实与当前实现一致
- [ ] 剩余边界已经明确记录
```
